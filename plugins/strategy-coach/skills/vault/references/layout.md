# Vault layout

Load only when writing. Both notes below start with the marker line, where `YYYY-MM-DD` is today:

```
> Generated by /strategy-coach:vault · YYYY-MM-DD
```

The marker is the overwrite permission. Absent means hand-written, and hand-written files are
never regenerated silently, by any skill in this marketplace.

## The layout this skill establishes

```
docs/
  home.md            <- the hub, written here
  conventions.md     <- written here
  00-index.md        <- /atlas-coach:ingest owns this; link only
  business/          <- /strategy-coach:blueprint writes here
  features/<slug>/   <- /strategy-coach:feature writes here
  onboarding/        <- /investigation-coach:onboard and :map own this
  study/             <- /investigation-coach:study owns this
  market/            <- /strategy-coach:market writes here
  research/          <- /atlas-coach:research owns this
```

## home.md

Links only, one line of context each — never a bare list. Include a section only when the target
exists; a hub that links to nothing is worse than a short hub.

```markdown
> Generated by /strategy-coach:vault · YYYY-MM-DD

# <Project> — documentation

## The business
- [[business/overview]] — the domain this project serves, and the processes in it
- [[business/actors]] — who uses this, and what each of them is trying to finish
- [[business/glossary]] — the words the team says, and what they are called in the code

## What we are building
- [[features/index]] — every specified feature, with its definition of done

## The code
- [[onboarding/index]] — setup, first task, and how the codebase is laid out
- [[onboarding/architecture]] — components and what talks to what
- [[study/index]] — why it is built this way

## Looking outward
- [[market/index]] — competitors, what their users complain about, and where the gap is
- [[business/industry]] — the rules and standards this industry is held to

## Sources
- [00-index](00-index.md) — documents ingested from outside the repo, with their origins
- [[conventions]] — how notes here are written, and which ones you may edit by hand
```

`market/` earns a section for the same reason every other directory does: this vault's own rule is
that nothing orphans, and market notes were being written into a tree whose hub had no way to reach
them. Link the individual analyses when there is no `market/index`.

The `00-index` link is a plain markdown link, not a wikilink: it belongs to another skill, and the
plain form signals "read, do not treat as part of this note set".

## conventions.md

````markdown
> Generated by /strategy-coach:vault · YYYY-MM-DD

# Conventions

## Which files you may edit by hand

Every generated note starts with a `> Generated by /<plugin>:<skill> · <date>` line. That line is
the tool's permission to rewrite the file. **Delete the line and the file becomes yours** — no
skill will touch it again, and the next run will report it as skipped rather than clobber it.

## Links

Wikilinks (`[[note-name]]`) between notes in this vault. Every note carries at least one outbound
link, so nothing orphans. Links to files owned by another skill use the plain markdown form.

## Frontmatter

Only what Obsidian actually reads:

```yaml
---
tags: [business, process]
aliases: [Checkout, order-checkout]
---
```

## Filenames

Sanitize `* " \ / : | ?` to `-`. A process named `order/fulfilment` becomes
`order-fulfilment.md`, keeping the real name as an `aliases:` entry.

## Evidence

A claim about the code carries `file:line`. A claim we could not verify against the code is marked
`INFERRED`. Blank is not an option — an unmarked guess is the one thing this vault cannot contain.
````
