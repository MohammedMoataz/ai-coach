# Vault layout

Load only when writing. Every note below carries the marker line, where `YYYY-MM-DD` is today:

```
> Generated by /strategy-coach:blueprint · YYYY-MM-DD
```

It goes on line 1 of a note that has no frontmatter, and directly **below** the `---` block on a
note that has one — Obsidian only parses frontmatter that starts at byte 0, and a marker above it
costs the note every tag it carries. Either way it lands within the first 10 lines, which is where
every skill here looks for it.

The marker is the overwrite permission. Absent means hand-written, and hand-written files are
never regenerated silently, by any skill in this marketplace.

**The vault root is `docs/`.** That is the folder to open in Obsidian — not the repo root, which
breaks every path wikilink here. Say so in the report.

## The layout this skill establishes

```
docs/
  home.md            <- the hub, written here
  conventions.md     <- written here
  00-index.md        <- /atlas-coach:ingest owns this; link only
  business/          <- /strategy-coach:blueprint writes here
  features/index.md  <- scaffolded here; /strategy-coach:feature appends to it
  features/<slug>/   <- /strategy-coach:feature writes here
  onboarding/        <- /investigation-coach:onboard and :map own this
  onboarding/components/  <- one note per service; /investigation-coach:map owns them
  .obsidian/graph.json    <- colour groups; /investigation-coach:map writes it once
  study/             <- /investigation-coach:study owns this
  market/            <- /atlas-coach:market writes here
  research/          <- /atlas-coach:research owns this
```

## home.md

Links only, one line of context each — never a bare list. Include a section only when the target
exists; a hub that links to nothing is worse than a short hub.

```markdown
> Generated by /strategy-coach:blueprint · YYYY-MM-DD

# <Project> — documentation

## The business
- [[business/overview]] — the domain this project serves, and the processes in it
- [[business/actors]] — who uses this, and what each of them is trying to finish
- [[business/glossary]] — the words the team says, and what they are called in the code

## What we are building
- [[features/index]] — every specified feature, with its definition of done

## The code
- [[onboarding/index]] — setup, first task, and how the codebase is laid out
- [[onboarding/architecture]] — components and what talks to what, with a note per component
- [[study/index]] — why it is built this way

## Looking outward
- [[market/index]] — competitors, what their users complain about, and where the gap is
- [[business/industry]] — the rules and standards this industry is held to

## Sources
- [00-index](00-index.md) — documents ingested from outside the repo, with their origins
- [[conventions]] — how notes here are written, and which ones you may edit by hand
```

`market/` earns a section for the same reason every other directory does: this vault's own rule is
that nothing orphans, and market notes were being written into a tree whose hub had no way to reach
them. Link the individual analyses when there is no `market/index`.

The `00-index` link is a plain markdown link, not a wikilink: it belongs to another skill, and the
plain form signals "read, do not treat as part of this note set".

## features/index.md

The hub `home.md` links as `[[features/index]]`. Scaffolded empty here so the link resolves from
day one; `/strategy-coach:feature` appends a row per specified feature.

```markdown
---
tags: [feature, index]
---
> Generated by /strategy-coach:blueprint · YYYY-MM-DD

# Features

*None yet — `/strategy-coach:feature <name>` writes the first one.*

Back to [[home]].
```

The link back to the hub is not filler: an empty index with no outbound link is the one note in a
fresh vault that breaks this vault's own no-orphan rule, and it stays empty until someone specifies
a feature.

## conventions.md

````markdown
> Generated by /strategy-coach:blueprint · YYYY-MM-DD

# Conventions

## Which files you may edit by hand

Every generated note carries a `> Generated by /<plugin>:<skill> · <date>` line in its first 10
lines — on line 1, or directly below the frontmatter block when there is one. That line is
the tool's permission to rewrite the file. **Delete the line and the file becomes yours** — no
skill will touch it again, and the next run will report it as skipped rather than clobber it.

## Where the vault root is

`docs/`. Open that folder in Obsidian, not the repo root — the paths in these links are relative
to it, and opening the wrong folder makes a correct vault look broken.

## Links

Wikilinks (`[[note-name]]`) between notes in this vault. Every note carries at least one outbound
link, so nothing orphans. A link that crosses a directory is vault-absolute from `docs/` —
`[[onboarding/components/api-gateway]]`, `[[business/processes/checkout]]` — and never uses `../`,
which Obsidian does not resolve. Inside one directory, a bare `[[name]]` is fine. Links to files
owned by another skill use the plain markdown form.

## Frontmatter

Only what Obsidian actually reads, and **always at the top of the file** — the `---` block first,
the `> Generated by` line directly below it. Obsidian parses frontmatter only when it starts at
byte 0, so a marker line above it silently discards every tag and alias in the note.

```yaml
---
tags: [business, process]
aliases: [Checkout, order-checkout]
---
```

## Tags

A fixed vocabulary, because the graph view colours by it:

| Tag | On |
|---|---|
| `business` | notes about the domain rather than the code |
| `process` | one business process, start to finish |
| `onboarding` | anything under `onboarding/` |
| `component` | one service or component, written by `/investigation-coach:map` |
| `feature` | a feature note or a spec |
| `study` | an explanation of why something is built as it is |

## The one generated `.obsidian/` file

No skill creates a `.obsidian/` directory, with a single exception:
`/investigation-coach:map` writes `.obsidian/graph.json` **once, only when it is absent**, to give
the graph its colour groups. It is committed; `.gitignore` covers `docs/.obsidian/workspace*` and
`docs/.obsidian/cache/` only. Edit it freely — nothing will overwrite it.

## Filenames

Sanitize `* " \ / : | ?` to `-`. A process named `order/fulfilment` becomes
`order-fulfilment.md`, keeping the real name as an `aliases:` entry.

## Evidence

A claim about the code carries `file:line`. A claim we could not verify against the code is marked
`INFERRED`. Blank is not an option — an unmarked guess is the one thing this vault cannot contain.
````
