# draw.io diagrams (.drawio)

Load only when `--diagrams drawio` was asked for. Produces `.drawio` files: plain XML, committed to
the repo, editable by anyone with a free tool and no account.

## Why this exists alongside mermaid

Three renderers, three different jobs. Pick by who has to *change* the diagram, not by which looks
best.

| | Mermaid | draw.io | Miro |
|---|---|---|---|
| Cost | free | free, open source, no account | subscription limits real use |
| Renders in GitHub | yes, natively | **no** — needs a viewer | n/a, it is a website |
| Auto-layout | yes | **no** — you place every box | yes-ish |
| Hand-editable by a non-developer | no, it is code | **yes — drag a box** | yes |
| Diffs in a pull request | yes, cleanly | yes, verbosely | no |
| Real-time, several people at once | no | no | yes |

**Mermaid stays the default** because it costs nothing, lays itself out, and renders where the code
review happens. Reach for draw.io when a diagram will be *maintained by hand* — by a product owner,
an architect, someone who will never edit a fenced code block. That is the gap Miro filled at the
price of a subscription, and a committed file fills for free.

## Honest limits, before you generate one

- **No auto-layout.** You compute every `x`/`y`. A generated diagram with overlapping boxes is worse
  than no diagram, so follow the grid rule below rather than improvising coordinates.
- **GitHub will not render it.** Viewing needs one of: the VS Code extension
  (`hediet.vscode-drawio`), the free desktop app, or app.diagrams.net. Say so when you hand the file
  over — a diagram nobody can open is not a deliverable. Obsidian needs a community plugin.
- **Keep it uncompressed.** draw.io can deflate+base64 the payload; never do that here. Plain XML is
  what makes the file reviewable, and the app reads plain XML fine.
- `.drawio.svg` and `.drawio.png` render everywhere *and* stay editable, but they are exports from
  the app — the SVG has to be genuinely drawn. Do not hand-write one. Generate `.drawio` and let the
  user export if they want the embeddable form.

## Skeleton

Uncompressed, one `<diagram>` per view. The comment is the overwrite marker, same rule as every
other generated file: remove it and the file is yours, and no skill will rewrite it.

```xml
<mxfile host="app.diagrams.net">
  <!-- Generated by /investigation-coach:map · YYYY-MM-DD -->
  <diagram id="context" name="Context">
    <mxGraphModel dx="800" dy="600" grid="1" gridSize="10" page="1" pageWidth="1100" pageHeight="850">
      <root>
        <mxCell id="0" />
        <mxCell id="1" parent="0" />
        <mxCell id="api" value="Checkout API" style="rounded=1;whiteSpace=wrap;html=1;" vertex="1" parent="1">
          <mxGeometry x="80" y="80" width="160" height="60" as="geometry" />
        </mxCell>
        <mxCell id="stock" value="Stock service" style="rounded=1;whiteSpace=wrap;html=1;" vertex="1" parent="1">
          <mxGeometry x="320" y="80" width="160" height="60" as="geometry" />
        </mxCell>
        <mxCell id="e1" value="reserve 15 min" style="edgeStyle=orthogonalEdgeStyle;html=1;" edge="1" parent="1" source="api" target="stock">
          <mxGeometry relative="1" as="geometry" />
        </mxCell>
      </root>
    </mxGraphModel>
  </diagram>
</mxfile>
```

`id="0"` and `id="1"` are required and always exactly as shown — every real cell is `parent="1"`.
Ids must be unique within a diagram; use readable slugs, not counters, so a diff says which box
moved.

## The grid rule — this is what keeps it legible

Do not invent coordinates. Place on a fixed grid and the layout cannot collapse:

- Box: `width=160`, `height=60`. Wider only for a long label — never taller.
- Column pitch `240` (so `x` = 80, 320, 560, 800). Row pitch `120` (`y` = 80, 200, 320, 440).
- One **layer per row**: entry points on the top row, the services they call beneath, storage
  bottom. An edge that goes upward is a callback and deserves a label saying so.
- Max **6 columns × 5 rows** per diagram. More than 30 boxes is two diagrams; split by area and say
  so in the file's second `<diagram>` or a second file.
- Group a layer with a container cell placed *before* its children, `style="swimlane;"`, children
  keeping `parent="1"` — nesting parents is where hand-generated files go wrong. Prefer no groups
  over broken ones.

## The style strings worth knowing

Everything else is decoration. Do not colour by taste; colour only to carry meaning, and say what
the meaning is in the diagram's own legend box.

| Thing | `style=` |
|---|---|
| Service / component | `rounded=1;whiteSpace=wrap;html=1;` |
| External system | `rounded=0;whiteSpace=wrap;html=1;dashed=1;` |
| Datastore | `shape=cylinder3;whiteSpace=wrap;html=1;boundedLbl=1;` |
| Actor | `shape=umlActor;verticalLabelPosition=bottom;html=1;` |
| Note / legend | `shape=note;whiteSpace=wrap;html=1;size=14;` |
| Call | `edgeStyle=orthogonalEdgeStyle;html=1;` |
| Async / event | `edgeStyle=orthogonalEdgeStyle;html=1;dashed=1;` |
| Inferred edge | `edgeStyle=orthogonalEdgeStyle;html=1;dashed=1;strokeColor=#999999;` |

An `INFERRED` edge must be visually distinct *and* labelled, exactly as in the markdown tables. A
diagram that presents a guess as a fact is the one failure mode worth being strict about, because a
picture is believed harder than a sentence.

## Rules

- **Every box and edge traces to something real.** Same standard as the markdown: an edge you could
  not verify is dashed, grey, and labelled `INFERRED`.
- **Uncompressed XML, always.** A base64 blob in git is not a diagram, it is an attachment.
- **Regenerating replaces only files that still carry the marker comment.** Hand-edited means
  hand-owned.
- **Tell the user how to open it** in the report, once, with the VS Code extension named.
- **Never emit an empty diagram.** Nothing found is a sentence, not a blank canvas.
