# Analysis document and chart specs

Load before writing. The order of the sections is the point: the shape of the data comes before any
finding, and the critique comes before the reader forms an opinion.

## The document

```markdown
> Generated by /analysis-coach:insight · YYYY-MM-DD

# <Domain> — <the decision this informs>

## What this data is
One row per <grain>. <n> rows, <first date> to <last date>, from <source>.
Columns used: <list>. Ignored: <list, and why>.

## What is missing
- No rows between 2026-03-14 and 2026-03-22 (<what that period was>).
- `channel` is null on 11% of rows, all before the January migration.

## Findings
### F1 — <the claim, as a sentence that could be false>
<The numbers, each with its denominator.> <What would have to be true for this to be causal, and
whether this data can tell.>

## Critique
### Against F1
<What else would produce this pattern. Composition change? Subgroup driving it? Window too short?>
**Revision:** <what changed in F1 after this, or "unchanged — the objection does not hold because …">

## Dropped
- <The reading that did not survive> — dropped because <reason>. Kept here so it is not
  rediscovered next quarter.

## What this data cannot answer
<The questions someone will ask that this dataset has no way to settle.>
```

## Generating readings that are actually different

Three readings that agree are one reading written three times. Force them apart by changing the
axis, not the wording:

- **The obvious one** — the pattern in the measure everyone already watches.
- **A different dimension** — the same question by time, by segment, by cohort, by channel. A
  monthly total that is flat can hide two segments moving in opposite directions.
- **The one that would be bad news** — deliberately look for the reading a stakeholder would not
  want. It is the one nobody generates by accident, and it is where the value is.

## The critique pass

Four questions, every time. They are not a checklist to be recited — each one has killed a real
finding:

1. **What else produces this pattern?** Name at least one alternative explanation. "Nothing else
   could" is almost never true and should be argued for, not asserted.
2. **Is the denominator right?** A rise in refunds against a rise in orders may be a flat rate.
3. **Is it composition?** An average that moves because the mix changed, while every component
   stayed still, is the single most common false finding in business data.
4. **Would a shorter or longer window say something different?** If the finding depends on the
   window, that dependence is the finding.

Write the answers down before revising. Reflexion's mechanism (Shinn et al., arXiv:2303.11366) is
that the criticism is *written and then fed back in* — re-reading and hoping is not the same
operation and does not have the same effect.

## Chart specs

A chart is a claim, so its title is the claim. Specify enough that someone else could build it
without asking:

```markdown
### Chart for F1
- **Claim (the title):** Refund rate doubled for wholesale after the March pricing change
- **Type:** line, one series per segment
- **X:** `order_date` truncated to week
- **Y:** `refunds / orders` as a percentage
- **Filter:** `channel = 'wholesale'`, excluding the gap 2026-03-14 to 2026-03-22
- **Annotate:** vertical rule at the pricing change, and the excluded gap marked as excluded
```

Rules that are not style preferences:

- **Excluded data is drawn as excluded**, never silently dropped — a gap that looks like a
  continuous line is a lie the chart tells on its own.
- **Truncated axes are labelled as truncated.** A y-axis starting at 90% turns a rounding error
  into a cliff.
- **One claim per chart.** A chart supporting two findings supports neither clearly.
- No chart for a finding that did not survive the critique. It survived or it is in **Dropped**.
