# Engine as CLI and library

## What it is here
One file, `plugins/ai-coach-core/hooks/engine.js` (~1,390 lines), exports ~60 functions for the
hooks that `require` it, and runs a `cli()` switch when invoked directly — the same brain behind
two mouths.

## Why here
Hooks and skills live in different worlds: hooks are Node processes inside the plugin dir; skills
are markdown instructions that can only shell out. A shared library alone couldn't serve skills
(plugin paths are ephemeral and siblings can't traverse); a CLI alone would cost a process spawn
per hook call. Serving both from one file keeps a single source of truth for ranking, storage and
privacy rules.

## Where to see it
engine.js:1377-1388 (`module.exports`), engine.js:1389 (`if (require.main === module) cli()`),
and the consumer sides: session-start.js:34 (`require('./engine.js')`) vs any SKILL.md's
`ENGINE` alias (`node "$HOME/.ai-coach/bin/engine.js"`).

## What it trades away
The file is big and grows every release; there is no module boundary inside it. The tests accept
that: one suite drives the library surface, another drives the binaries end to end.

## How it interacts
[[../cross-cutting/fail-open-hooks]] — the callers that must survive its failures.
`bootstrap()` (engine.js:89) is the trick that makes the CLI path stable: it copies the engine to
`~/.ai-coach/bin/` and refreshes on diff.
