# Fail-open hooks

## What it is here
Every hook wraps its whole body in try/catch, logs the failure to `~/.ai-coach/log.jsonl`, and
exits 0 anyway. The single exception is deliberate: the secrets guard exits 2 to block a tool
call carrying real credentials.

## Why here
A hook runs on every session of every teammate. A crashing coach that blocks Claude Code gets
uninstalled the same day — so the failure budget is spent on diagnosability (the log) instead of
on correctness guarantees. "AI Coach just stopped working" must always be answerable from the
log file.

## Where to see it
session-start.js:75-78 (catch → log → exit 0), guard.js:52 (the one exit 2),
engine.js:22-25 (`log()` with rotation). The test suites assert exit codes on garbage stdin.

## What it trades away
Silent feature loss: a broken brief just doesn't appear. The log is the only tell, and the
`/memory-coach:doctor` skill exists mostly to notice this.

## How it interacts
[[../engine/engine-as-cli-and-library]] — the library these hooks call; its own reads are
guarded (`safeRead`, engine.js:34) so a planted symlink can't crash or leak into a session.
