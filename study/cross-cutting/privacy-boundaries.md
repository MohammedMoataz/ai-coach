# Privacy boundaries

## What it is here
A single direction rule: aggregates travel, text stays. Prompt text never leaves the machine
(only detector flag names do); correction messages stay local (an `outcomes` count travels
instead); security-finding evidence never enters a seed; per-person analytics don't exist.

## Why here
The product moves knowledge between teammates over git — the one thing that must never ride
along is something a teammate didn't choose to publish. The seed is PR-reviewable precisely so a
human can check that; the schema makes the check trivial by never mixing text-bearing tables into
the export.

## Where to see it
`seedExport` (engine.js:971) is table-explicit — memories, sessions, prompt_signals; a regression
test locks `SECRET-EVIDENCE-XYZ` out of the seed format (engine.test.js, v0.3.0 section).
`<private>` spans are stripped in the observation hook before disk. The findings table comment in
memory/schema.sql:106 states LOCAL ONLY.

## What it trades away
The pooled team view can't show who needs help — deliberately. A report that ranks colleagues
gets the plugin uninstalled; the engine returns a pool size and nothing else identifying.
